# 검증 스크립트 (cold review 용)

PowerShell 5.1 에서 `powershell -ExecutionPolicy Bypass -File <스크립트> [exe 경로]` 로 실행한다. exe 를 주지 않으면 `src\OneKey\OneKey.csproj` 의 버전으로 `build\<버전>\1Key.exe` 를 쓴다.

## 언제 무엇을 돌리나 (2026-10-05 사용자·Codex 합의)

| 변경 수준 | 시험 |
|---|---|
| 문구·색상·단순 배치, 주석, 판 번호 | 빌드 + 그 화면 확인. 창 시험 없음 |
| 특정 기능 로직(저장·입력·잠금·바로 실행 등) | 그 기능의 시험만: `run-all.ps1 -Only <스크립트>` 또는 `run-all.ps1`(바뀐 파일 → 시험 지도) |
| TODO 마일스톤 끝 | 그 마일스톤 동안 바뀐 파일의 시험: `run-all.ps1 -Base <마일스톤 시작 커밋>` |
| 모든 수정이 끝난 출시 후보 | 통합 시험 1회: `run-all.ps1 -All` |

- 실패하면 원인과 영향 범위만 다시 돈다. 같은 결과가 나올 시험을 반복하지 않는다.
- 한 번 확인으로 끝나는 시험은 기본 실행에서 빠져 있다: `launch.ps1 -Edge`(LA16–30), `tamper.ps1` 의 예전 판 호환, mem·fxmem, lockwidget cycles·resources, shots, dw-compare. 그 코드나 저장 형식을 바꿀 때만 손으로 돌린다.
- 시험을 시작하기 전에 고른 스크립트와 예상 시간을 사용자에게 말한다(`run-all.ps1 -DryRun` 으로 고른 목록 확인).

## 판정 방식 (T18, 0.2.29 부터)

모든 스크립트는 `lib\Check.ps1` 을 불러 같은 방식으로 판정한다.

- 스크립트 머리에 `Start-Checks -Required @(...)` 로 **반드시 나와야 하는 검사 ID 전체**를 선언한다.
- 각 검사는 `Check <ID> <기대값> <실제값> <설명>` 한 줄이다. 기대값과 실제값을 글자 그대로(대소문자 구분) 비교한다.
- 끝의 `Complete-Checks` 가 다음 중 하나라도 있으면 종료 코드 1 로 끝낸다: 실패한 검사, 선언했는데 나오지 않은 ID, 두 번 나온 ID, 선언하지 않은 ID, `Add-Failure`(예외·창 없음), 그리고 `$Error` 에 남은 **모든** 오류 기록(비종료 오류 포함).
- 출력(`ok` / `FAIL` 줄)은 보고용일 뿐이고, 판정은 기록된 결과로만 한다. 로그 글자를 세지 않는다.
- 정리용 명령은 `-ErrorAction Ignore` 를 쓴다. `SilentlyContinue` 는 `$Error` 에 기록을 남겨 실패로 집계된다.
- `selfcheck.ps1` 이 판정 라이브러리 자체를 검사한다: 검사 실패·ID 누락·중복·미선언·중복 선언·`Write-Error`·조용한 오류·`Add-Failure`·잡힌 예외·대소문자 차이는 모두 종료 코드 1, 깨끗한 경우와 `Ignore`·`Clear-ExpectedError` 는 0.

## 격리

모두 `ONEKEY_TEST=1` + 별도 설정 폴더(`%TEMP%\1Key-tests`, `ONEKEY_TEST_DIR` 로 변경) + 인스턴스 접미사로 실행된다.
접미사는 뮤텍스·창 클래스뿐 아니라 **자동 실행 등록 이름**에도 붙는다(Run 값 `1Key<접미사>`, 작업 `1Key_AutoStart<접미사>`).
그래서 실제 사용자의 프로세스, `%LOCALAPPDATA%\1Key\config.dat`, Run 값 `1Key`, 작업 `1Key_AutoStart` 는 건드리지 않는다.
각 스크립트는 시작과 끝(`finally`)에서 **그 접미사의 창을 가진 프로세스만** 끝낸다. 실행 중 테스트 창과 안내 상자가 잠깐 뜬다. 닫지 말고 두면 스크립트가 처리한다.

`clip.ps1` 은 실제 Windows 클립보드를 몇 초 쓴다. 클립보드에 평문 외 형식(HTML·RTF·그림·파일 등)이 있으면 아무것도 바꾸지 않고 종료 코드 2 로 끝낸다. 누가 클립보드를 바꿨는지는 내용이 아니라 **실행 표식**으로 판단한다(0.2.39): 실행마다 16바이트 무작위 값을 만들어 형식 `1Key.TestRun` 으로, 시험 도구와 앱(`ONEKEY_TEST_CLIP_RUN`)이 시험 중의 모든 쓰기에 함께 넣는다. 다른 프로그램이 복사하거나 비우면 표식이 사라진다. 앱은 처음 열 때, 도구는 쓰기 전마다 한 번 연 클립보드 안에서 표식(과 아는 경우 일련번호)을 확인하고, 어긋나면 그 자리에서 멈추고 클립보드를 그대로 둔 채 실패("DISTURBED", 앱은 종료 코드 6)로 기록한다. 도구의 쓰기는 모두 결과를 확인한다(-1 열지 못함, -2 우리 것 아님, -3 메모리, -4 비우기 실패, -5 비운 뒤 실패·표식만 남김, -6 상태 모름). 끝의 되돌리기는 성공했을 때만 "되돌렸다"고 적는다. 앱이 다른 프로그램을 흉내 낼 때(`clip:ext-*`, `intrude-*`)도 같은 열기 안에서 실행 표식을 확인한 뒤에만 비운다(0.2.40, 없으면 흉내를 내지 않고 종료 코드 6). 흉내나 시험 표식 쓰기가 실패하면 비밀번호 더미를 되돌린 뒤 종료 코드 7 로 시험 오류를 알린다. **보장 범위**: 클립보드를 비우는 보통의 복사·잘라내기·비우기(실행 표식이 지워진다)로부터의 보호다. 비우지 않고 형식만 바꾸는 프로그램(표식이 남는다)은 번호를 알고 비교하는 곳, 즉 번호를 아는 동안의 도구 쓰기에서만 잡힌다. 앱이 처음 열 때, -5 실패 뒤, 흉내 뒤 되찾을 때는 표식만 보고, 닫은 직후 번호를 읽기 전 순간도 남는다. 완전한 격리가 필요하면 별도 Windows 세션에서 돌린다. PC 를 쓰지 않을 때 돌린다. 시험 도구가 쓰는 글과 되돌린 사용자 글에는 클립보드 기록·클라우드 제외 표시를 한다.

모든 스크립트는 판정 끝에 시험한 exe 의 경로·버전·SHA-256 을 한 줄로 남긴다.

## 자동화하지 않은 것

실제 Windows 세션 잠금(Win+L; 처리 함수는 `WM_WTSSESSION_CHANGE` 로 시험), 실제 UAC 창, 실제 관리자 권한 대상 창, 실제 브라우저 페이지 안의 입력란(Chrome 업무 화면에서 Enter 전송과 "보내지 않기" 항목의 Enter 생략만 2026-09-29 사용자가 확인), Narrator 낭독, 실제 125/150% 모니터.

## 주의

스크립트가 도중에 죽으면 테스트 인스턴스가 남을 수 있다. 다음 실행이 시작할 때 같은 접미사의 인스턴스를 먼저 끝내므로 보통은 다시 실행하면 된다.
